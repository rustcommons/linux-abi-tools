# Requirements and documentation trace

## Scope and sources

This index covers all five linux-abi-tools workspace packages. It records
confirmed constraints from [AGENTS.md](../AGENTS.md), the maintained guides below,
and existing provider decisions; it does not authorize new product scope or
turn roadmap ideas into requirements. `LAT-REQ` IDs are repository-scoped and
stable. No earlier requirement IDs were found in this repository at the audit
baseline, main `4679b3565103aa1fcb7e3a5538ce864b3f0d2608` (2026-11-01).
Existing finding IDs F1/F3/F4/F5, R1/R2 and U1–U3 remain unchanged.

The current product release is all five crates **0.4.0**, tag `v0.4.0`, exact
commit `7ce231df7128582a355c2dce47ae6436364d5e88`. See the [published producer
record](RELEASING.md#published-040-archives-and-documentation). The seven-tag GitHub
release-note backfill and registered documentation CI are
[complete](RELEASING.md#release-documentation-backfill-completed-2026-11-02),
verified on documentation merge `6f1e5bdeb06f168bf29f1d7bddf937c028e5cb60`;
source tags and registry archives remain unchanged. Cargo's new registry
adoption is authorized and remains a separate consumer gate, not claimed complete
here. The [0.3.3 producer and cargo-libc 0.2.2 adoption record](REVIEW-FIXES.md#published-033-archives-and-documentation)
is historical and retains its original outcomes.

### Evidence catalogue

The initial documentation audit used source/manifest/workflow inspection and CLI
help or read-only query checks on 2026-11-01; that audit did not rerun Rust suites,
provider builds, data regeneration or publication. Release-specific evidence added
on 2026-11-02 is bounded by its named source, commands and records. A configured CI
job is an intended gate, not evidence of a successful run. Earlier results below
retain their exact scope:

Consumer adoption remains separate.
- **Historical 0.3.3 release checks:** [focused run 41268289801](https://github.com/rustcommons/linux-abi-tools/actions/runs/41268289801)
  passed for candidate `dc36fb26aaf06b3740322bc805b67d8b7ebfdfe5` on 2026-11-01:
  Ubuntu/Windows all-target tests/Clippy, doctests, no-default root tests, Rust 1.90
  all-target check, official Rust 1.90 ELF acceptance and native x86_64 kernel
  simulation. The [release record](REVIEW-FIXES.md#candidate-gates-and-publication-handoff)
  distinguishes implementation `6604ceea`, final documentation head `bf61fe11`
  and clean merged-package checks. Final archives identify `d483fd5a`.
- **Provider inputs:** [run 38338235109](https://github.com/rustcommons/linux-abi-tools/actions/runs/38338235109),
  `188121f`, 2026-10-12, records source/container comparisons and scoped C/Cargo
  application checks for 2.17–2.44; [PROVIDERS.md](PROVIDERS.md#delivery-modes-per-release)
  preserves compiler/input/verdict details. These are historical provider results,
  not a fresh full matrix against 0.3.3 or universal target qualification.
- **Consumer adoption:** the pinned [cargo-libc 0.2.2 record](https://github.com/rustcommons/cargo-libc/blob/1ca27da9086ebf6cf19a6f2c0e858108b38cac46/docs/RELEASE-0.2.2.md)

  2026-11-01. Consumer evidence, not producer test counts, supports those claims.

`Verified` below always means the named bounded evidence, not all environments.
`Implemented—partial verification` identifies implemented contracts with explicit
coverage gaps; `Planned`, `Deferred` and `Not applicable` describe their stated
scope only. No new feature commitment is created by this index.

## Maintenance

Preserve IDs permanently; append new IDs without renumbering/reuse. When behavior,
interface, floor, scope or evidence changes, update the affected row and guide
together. Keep historical outcomes and existing finding IDs intact; supersede
with a dated pointer rather than rewriting a result. Record exact commands,
revision/date, environment, and limits. Mark missing evidence explicitly.

For docs-only edits check source/CLI syntax, links/anchors, rendering, unchanged
instruction sections/shim, and diff scope. Changed executable examples need
appropriate validation; changed Rust doctests need meaningful compilation/doc
checks. Do not run provider matrices or regenerate data merely for trace links.
Merge only after independent review and verification of the central shared link.
