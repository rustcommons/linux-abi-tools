# v0.3.3 — Bound ELF processing and preserve container input

Malformed ELF processing is bounded without rejecting valid large fixed tables, and Docker/Podman runners retain explicitly requested environment and redirected stdin.

Original registry publication date (UTC): **2026-11-01**. Source tag
[`v0.3.3`](https://github.com/rustcommons/linux-abi-tools/tree/v0.3.3), commit
[`d483fd5a58e1361d008f06db5989acef72a84e54`](https://github.com/rustcommons/linux-abi-tools/commit/d483fd5a58e1361d008f06db5989acef72a84e54).
All five workspace packages were published at 0.3.3; all five are non-yanked as
verified on 2026-11-02. This is a crate release, not a source-only historical tag.

These notes were reconstructed on 2026-11-02 and were not part of the original
source tag or immutable registry archives. A later GitHub Release posting date is
the documentation backfill date, not the original registry publication date.

## Changes

- ELF parsing uses checked ranges and bounded version-chain work; valid large fixed symbol/relocation tables, including the recorded Rust Cargo and rustc-driver files, remain accepted.
- Equivalent executable aliases coalesce while distinct address evidence remains represented. Excessive site expansion returns an explicit resource error rather than truncating evidence.
- Container execution forwards explicit environment selections and redirected stdin. Credentials are forwarded only when explicitly selected; the whole host environment is not implicitly copied.
- All five packages share 0.3.3. Upstream glibc inputs and kernel profile data are unchanged.

## Upgrade

Published 0.3.2 remains unchanged and lacks these fixes. Raise scanner/kernel dependency minima to 0.3.3 when consumers need to exclude older parser/runner versions for every resolution; merely refreshing one lock does not enforce those floors for other users. The later derived clock overlay API is not present in 0.3.3.

## Validation and limits

The [release/evidence record](https://github.com/rustcommons/linux-abi-tools/blob/main/docs/REVIEW-FIXES.md#published-033-archives-and-documentation) distinguishes independently reviewed source `6604ceea`, evidence-only heads and the clean merged release. It preserves malformed-input caps, valid Rust 1.90 file acceptance, stdout/container checks, [focused run 41268289801](https://github.com/rustcommons/linux-abi-tools/actions/runs/41268289801), package checksums and scoped consumer adoption. Superseded `c04269a` evidence is historical. Site/input budgets can still reject valid unusually complex files; scans/simulation do not qualify an actual old kernel/userland.

The 2026-11-02 backfill audit independently downloaded all five version-0.3.3
archives, matched their registry checksums and clean VCS identities to the source
commit above, and inspected source/tag differences. This confirms artifact
identity/availability, not historical test execution. No Rust suite was rerun for
this documentation backfill. Distributions remain crates.io packages; no new
standalone binaries or SDK assets accompany these notes.
