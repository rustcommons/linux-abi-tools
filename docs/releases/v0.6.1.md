# linux-abi-tools workspace 0.6.1

Patch release of all five lockstep producer crates: `linux-targets`,
`kernel-abi-tools`, `linux-abi-scan`, `libc-abi-tools` and `linux-abi-tools`.
This is the first release published only through the owner-approved crates.io
Trusted Publishing workflow.

## Changes

- kernel-abi-tools: the private syscall/madvise table decoder now returns an
  error for a malformed row instead of panicking. That covers a wrong column
  count, an out-of-range or negative number, and an invalid kernel version.
  The problem was found while adding parser fuzz targets, and a regression
  test now covers it.
- Impact: only malformed or untrusted kernel table input was affected. No public
  API accepts external table text; `syscalls()`, `madvise_advice()` and profile
  generation read only the bundled tables. Those tables are valid, so results are
  identical to 0.6.0. The release hardens the decoder for fuzzing and future use.
- The other four crates have no code changes. They move to 0.6.1 under the
  lockstep version policy, with inter-crate requirements raised to 0.6.1.

## Upgrade

No API, CLI, data or profile changes. MSRV stays 1.90.

The root crate version is part of the provider-cache input key. After
upgrading, the next `libc-abi provider prepare` creates a fresh generation under
a new key, the same as any version change. Existing descriptors and returned
paths stay valid until you remove them.

## Validation and limits

Workspace tests, Clippy and formatting passed on the release PR, along with the
full CI matrix and ClusterFuzzLite PR fuzzing. The release record lists the exact
merge, the official archive checksums, docs.rs builds and a fresh registry
consumer build once publication is verified.

Fuzzing is bounded: 300 s per PR and 1800 s weekly with AddressSanitizer. It
does not prove the parsers are free of bugs. No new old-OS, kernel, tier 3 or
prebuilt-provider qualification is claimed.
