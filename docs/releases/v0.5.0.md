# 0.5.0 — reusable byte-content SHA-256

Release preparation dated 2026-11-03. Not yet published or tagged; the final
merged source, UTC publication date and archive checksums will be recorded after
the authorized publisher completes publication. All five workspace crates are
prepared at 0.5.0. Existing 0.4.0 packages remain immutable.

## Changes

`libc_abi_tools::content_sha256(&[u8]) -> String` returns the conventional full
SHA-256 digest of exactly the supplied bytes as 64 lowercase hexadecimal digits.
It exposes the existing std-only implementation for consumer file-identity
reports, without file access, tools, cache activity or authentication. The
umbrella re-export exposes it as `linux_abi_tools::libc::content_sha256`.

This is a 0.x minor release because the maintained policy assigns public API
additions to minor versions. All five crates stay in lockstep; kernel, scanner,
target-selection, provider and clock-overlay implementations are unchanged.
No LLVM/unwinder preparation or replacement is included. Upstream glibc data and
source dependencies remain at their existing requirements and locked 0.1.0 inputs.

## Upgrade

Consumers needing the utility must raise their `libc-abi-tools` minimum to
`0.5.0` (or the umbrella minimum if using its re-export), then update their real
registry lock. A source patch or lock-only update does not enforce that minimum
for all resolutions. Consumer registry adoption, package installation and checker
release are separate gates after producer publication.

The root package version is part of provider-cache identity. Its 0.5.0 upgrade
can require preparation under a new key even though provider implementation and
recorded interfaces are unchanged. Keep required native tools and embedded inputs
available for offline source preparation. Container preparation can require an
engine, images, archives/network and host tools. Existing export/import checks
and machine-local GCC startup handling still apply; an old-version cache or
export is not a promise of transparent reuse across tool versions or machines.
See the maintained provider guide before transferring inputs.

## Validation and limits

Candidate-local checks passed on Linux aarch64: 128 workspace all-target tests
(three explicit external-fixture ignores), six doctests, 58 root no-default
all-target tests (two explicit ignores), fmt, Clippy and API docs with warnings
denied, Rust 1.90 workspace all-target checking, and all-five workspace package
verification/allowlist/license audits. Clean package/VCS identities and the named
ignored cases are tracked in the release record and PR #12. These local checks
are not native x86_64 or Windows execution evidence. Hosted checks and independent
review remain separate from local results.
No fresh broad provider/kernel container matrix is required by this pure wrapper
and version change. Earlier provider/clock/kernel results retain their original
scope. Tier 3 old-system qualification remains deferred and is not an ordinary
release blocker; prebuilt-provider legal review remains unchanged.

A content digest is not authenticity, signature verification, ELF validation or
runtime compatibility evidence. This release adds no GCC-floor checker and makes
no dependency-removal, new host-platform or unwinder compatibility claim.
