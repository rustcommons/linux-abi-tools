# v0.2.0 — Explicit providers for every glibc release from 2.17 to 2.44

Explicit provider selection now accepts every recorded glibc release from 2.17 through 2.44, rather than only 2.17, 2.18 and 2.22.

Original registry publication date (UTC): **2026-10-11**. Source tag
[`v0.2.0`](https://github.com/rustcommons/linux-abi-tools/tree/v0.2.0), commit
[`921cf79cc2780a88e917aa9542955a746214f6a1`](https://github.com/rustcommons/linux-abi-tools/commit/921cf79cc2780a88e917aa9542955a746214f6a1).
All five workspace packages were published at 0.2.0; all five are non-yanked as
verified on 2026-11-02. This is a crate release, not a source-only historical tag.

These notes were reconstructed on 2026-11-02 and were not part of the original
source tag or immutable registry archives. A later GitHub Release posting date is
the documentation backfill date, not the original registry publication date.

## Changes

- `libc-abi-tools` extends `provider::RELEASES` to all 28 releases, keeping exact selection and refusal of a mismatched descriptor.
- `libpthread_nonshared.a` is required only before glibc 2.28, matching the recorded inputs.
- Per-release source-input recipes and measured ELF/conformance evidence cover the added releases. The other four packages share the workspace version without a new product API or implementation in their source bodies.

## Upgrade

Raise the selected package requirement to the 0.2 series to use the expanded provider API; a 0.1 requirement does not automatically select 0.2. Existing supported descriptors remain version-specific. Supply the pinned inputs for the chosen release; this version does not yet offer the automatic `provider prepare` delivery/cache API added in 0.3.0.

## Validation and limits

The [tagged validation record](https://github.com/rustcommons/linux-abi-tools/blob/v0.2.0/docs/VALIDATION.md) records per-release checks and [84 hosted provider jobs](https://github.com/rustcommons/linux-abi-tools/actions/runs/38158161339) at `ae68bf63f5ddde7fc7852e76eab83ad2c1beb2c0`: 28 preparations and 56 applications. Those checks used their named compilers, consumer revisions and modern host kernels. They are not a fresh final-tag or all-distro qualification. The [provider index](https://github.com/rustcommons/linux-abi-tools/blob/v0.2.0/docs/PROVIDERS.md) retains the per-release counts and limitations; a separate final-tag consolidated release audit was not recovered.

The 2026-11-02 backfill audit independently downloaded all five version-0.2.0
archives, matched their registry checksums and clean VCS identities to the source
commit above, and inspected source/tag differences. This confirms artifact
identity/availability, not historical test execution. No Rust suite was rerun for
this documentation backfill. Distributions remain crates.io packages; no new
standalone binaries or SDK assets accompany these notes.
