# v0.3.2 — Handle closed stdout without hiding failures

Closing a CLI output pipe no longer causes a tool-owned stdout panic, while findings and later operation failures still retain their error status.

Original registry publication date (UTC): **2026-10-31**. Source tag
[`v0.3.2`](https://github.com/rustcommons/linux-abi-tools/tree/v0.3.2), commit
[`d404073e2329405e9e6f2dd1005fd8671e0d0f41`](https://github.com/rustcommons/linux-abi-tools/commit/d404073e2329405e9e6f2dd1005fd8671e0d0f41).
All five workspace packages were published at 0.3.2; all five are non-yanked as
verified on 2026-11-02. This is a crate release, not a source-only historical tag.

These notes were reconstructed on 2026-11-02 and were not part of the original

the documentation backfill date, not the original registry publication date.

## Changes

- `libc-abi`, the shared provider CLI, `linux-abi-scan` and kernel CLI output paths handle `BrokenPipe` at write/flush boundaries.
- Provider operations continue after output closes and still report later failures. Scanner findings remain exit 1; usage/read errors remain exit 2. Genuine output errors still fail, and ordinary output bytes stay unchanged.
- Packaged READMEs and user/maintainer guides clarify installation, package/CLI identities and feature choices. The five versions move together without ABI-data, API, upstream-input or MSRV changes.

## Upgrade

Update the CLI package that owns the affected command. To pick up shared provider output handling in a consuming application, resolve the updated `libc-abi-tools` too; a local source patch does not repair an older published dependency. This release does not contain the later 0.3.3 ELF bounds/alias-budget or container environment/stdin fixes.
